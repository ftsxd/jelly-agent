# 读回闭环的成本与效果测量

回答三个问题，用实测而不是论证：

- 小任务有没有回归
- 大任务能不能完成
- 完成一次实际花多少钱

## 为什么在仓库里

前一版写在临时目录，跨天被清掉了，测量就没法复现。测量脚手架和被测代码
一起版本化，才谈得上"对照"——否则每次都是新造一把尺子量新的东西。

## 数据

`../internal/engine/testdata/fake_logs_mcp.py`，一个 stdio MCP 服务器，
返回合成的服务日志，答案是预先植入的：

| 植入项 | 位置 | 针对的失败模式 |
|---|---|---|
| `ROOT CAUSE ... db-node-3` | 文件 50% 处 | 只读开头就答不出 |
| `FINAL: failover ... db-node-5` | 末尾第 3 行 | 只读开头会"看起来成功"却漏掉 |
| `TIMEOUT` 精确 N 次 | 全文均匀分布 | 统计题必须全量计数，不能靠眼估 |

`FAKE_LOG_LINES` 控制规模，所以同一个服务器同时供小、大两种场景，
两次运行之间只有被测的那一个变量不同。

## 基线是什么

不是另一个二进制，而是同一个二进制**不配 `context_window`**——这正是
动态预算出现之前的行为，也正是线上配置今天的样子：没有窗口就没有预算可算，
每份正文都整个进 prompt。

## 跑

    BENCH_RUNS=3 python3 bench/harness.py     # 写出 bench/results.json
    python3 bench/report.py                   # 打印对照表

`BENCH_ONLY=2-大` 可以只跑某一组。需要真实 provider 凭据
（读 `~/.jelly-agent/config.yaml`），会产生真实费用。

## 计价

单价取自厂商价目页（deepseek-v4-flash，2026-09-04 取）。非峰时为峰时半价，
峰时是 UTC 周一至周五 01–04 与 06–10 点，脚本按运行时刻自动判断。
单价写死在脚本里而不是问模型，因为记忆里的价格不能作为账单依据。
