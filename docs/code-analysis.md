# 代码分析 Agent

## Web 项目管理（推荐）

控制台 **代码 → 新建项目** 支持为不同项目保存仓库地址、分支、可分析的目录和凭据引用。

1. 填写项目名称、唯一标识、HTTPS Git 地址和分支。
2. 私有仓库填写服务进程中已有的令牌环境变量名，以及 Git 服务要求的用户名（默认 `oauth2`）；页面不保存令牌值。公有仓库留空即可。企业 CA 证书需要安装到服务端系统信任库。
3. 填写 **可分析的目录**：主分析目录填 `.` 表示整仓，填 `services/discount_coupon` 则只分析这个服务；再按需添加参考目录（如 `common`）。每个目录可以填业务名称和描述，Agent 用它把「订单服务」对应到实际路径。
4. 点击 **保存并同步**，或先保存、稍后点 **首次同步**。同步在后台执行，**关闭页面不会中断**；页面显示排队中 / 拉取代码中 / 已就绪。
5. 点击 **分配 Agent**，选一个负责分析的 Agent。
6. 让该 Agent 分析项目，例如“分析优惠券的核销链路，标出关键文件和行号”。

新项目默认不分配给任何 Agent。`root` 是单 Agent 模式的名称；命名 Agent 和子 Agent 分别分配，父节点的分配不自动传给子节点。取消分配和移除项目会阻止后续项目工具调用，即使当前对话还持有旧引擎。已开始的一次文件读取可以完成，已返回的内容和对话历史不会被清除。删除 Agent 时同步移除其项目分配。

旧数据中带有效期的授权继续按期失效，页面不再提供有效期选项。

### Agent 使用的工具

- `list_code_projects`：列出当前 Agent 被分配的项目、同步版本，以及每个项目可分析的目录及其业务名称与描述。
- `list_project_dir(project, path)`：浏览项目内目录。
- `grep_project_files(project, pattern, path, glob)`：定位代码；`path` 留空即搜索全部已配置目录。
- `read_project_file(project, path, offset, limit)`：按行读取文件。

Agent 身份由服务端绑定，不能通过工具参数冒用其他 Agent。每次文件访问重新校验分配关系，路径限定在**项目配置的目录**内——浏览、搜索、读取三个入口统一过滤，不是靠提示词约束。管理接口使用现有控制台管理员认证。

目录说明是用户维护的业务背景，不是已从代码验证的结论，也不会扩大可读范围。配置的目录在同步下来的代码里找不到时，页面列出具体路径，项目不显示为可分析。

### 目录范围怎么限制

快照目录仍是唯一的根，在它之上加一层仓库相对前缀白名单：一个路径必须同时在根之内且在某个配置目录之内才可达，两层检查都在符号链接解析之后进行，所以仓库里 checkin 的软链跑不出去。

作为配置目录祖先的路径（范围是 `services/discount_coupon` 时的 `services`）可以列出，但只显示通往范围的那个子目录，不显示其余兄弟目录。同名前缀不算包含：`services/order` 不会顺带放行 `services/orders`。

Agent 读回的路径始终是仓库相对路径，可以直接再传回去，也可以在工具之外引用。

专职代码分析 Agent 可以把 `code-analysis` 加入常驻工具组（`required_suites`），确保这四个工具不被工具数量预算裁掉。

### 存储和运行方式

保存在配置文件旁边的 `code-projects/` 目录；使用环境变量配置时默认是 `~/.jelly-agent/code-projects/`：

| 文件 | 内容 | 权限 |
|---|---|---|
| `projects.json` | 项目配置、分配关系、同步状态 | 0600 |
| `annotations.json` | 目录标注与草稿，**按仓库地址分组** | 0600 |
| `secrets.json` | 访问令牌 | 0600 |
| `cache-<项目 ID>.git/` | 指定分支的裸 Git 对象缓存，Agent 不可读 | 位于受保护的项目管理目录 |
| `snapshot-*/` | 代码快照 | — |

标注按仓库存而不是按项目存：同一个仓库建的多个项目共享同一份标注，标一次所有项目都受益，也不会各自漂移。读写都按各项目的分析范围过滤，范围外的目录既看不到也标不了。旧版本存在项目上的标注会在启动时自动迁移。

备份时包含整个目录，注意 0600 的权限别被备份工具放开。**此目录由单个服务进程管理，不支持多个进程同时共享写入**——进程内的互斥锁跨不了进程，两个进程同时写会丢更新、重复拉取、并且互相把对方正在跑的同步标记成中断。

同步由服务端 Git 执行，不依赖 Agent 技能，也不向 Agent 开放写入或拉取权限。仅支持 HTTPS，禁止 URL 内嵌凭据及 HTTP 重定向；不执行仓库 hooks，不递归拉取 submodule，快照移除 `.git` 和符号链接。Git LFS 文件保留指针，本版本不下载 LFS 对象。

首次同步下载指定分支最新提交所需的完整代码，并保留裸 Git 对象缓存；后续通过浅 `fetch` 复用已有对象，增量下载。版本未变且快照目录存在时，直接复用快照；有变化时，从本地缓存流式导出整棵代码树，校验后原子发布。升级后的第一次同步需要建立缓存，此后才享受增量下载。

目录配置只决定 Agent 能读哪些目录，不缩小缓存或快照范围。因此每个项目各占一份缓存和完整工作树——同一仓库建三个项目就是三份。改目录、名称、描述不需要重新同步。缓存不保存远端配置或访问令牌；导出时禁用 `export-ignore` 和 `export-subst`，避免仓库的发布打包规则遗漏或改写待分析代码。每 32 次成功 fetch 尝试回收缓存中的旧对象，维护最多等待 30 秒；回收失败在后续同步重试。同步期间旧、新快照与缓存会暂时并存。

同步在后台执行，与 HTTP 请求脱钩：关闭页面、代理断连都不会取消它。同一项目重复点击返回同一个任务，不会产生第二次拉取。服务重启会把中断的任务标记为「中断，可重试」，不自动续传。

上限可配置（`files.code_projects`）：

| 配置项 | 默认 |
|---|---|
| `sync_timeout_sec` | 1800（30 分钟） |
| `max_snapshot_mb` | 2048 |
| `max_snapshot_files` | 200000 |

默认值按整仓拉一个微服务大仓库来定——一个 126 服务的仓库工作树 400 MB / 18000 文件是常态。体积/文件数上限在发布前校验，不限制 Git 下载过程本身。

完整同步成功后才切换快照；失败保留上次可用版本并显示错误。修改仓库或分支会清除旧快照和对象缓存，需要重新同步；只改目录配置不会。移除项目会清理快照和缓存；进程异常退出可能留下未发布临时目录，可在服务停止后清理。当前提供手动同步，不包含定时同步。

### 与已有全局目录的区别

**高级：全局共享代码目录** 保留原有 `files.roots` 功能，所有 Agent 都能使用这些目录。它不能包含配置目录、项目管理目录或这些目录的上级路径；项目快照也不会自动加入脚本沙箱的可读目录。

项目分配控制本页管理的代码工具；已有对话、共享记忆、外部 MCP 和另行配置的脚本权限仍遵循各自的配置。分析 Agent 应只配置需要的工具，避免通过外部文件服务或过宽脚本权限另外暴露相同代码。

## 既有方式：共享目录与同步技能

把多个项目的代码定时同步到本地，再让一个专职 Agent 读它。这份文档说明怎么配，以及**哪些地方是真隔离、哪些只是约定**。

## 三层，职责分开

```
  周期任务 ──► repo-sync 技能 ──► sync.sh（git pull）
                                    │  沙箱：workspace-net + write_paths
                                    ▼
                              /data/repos/
                                ├── project-a/
                                └── project-b/
                                    ▲
  CodeAnalysis Agent ──► read_file / list_dir / grep_files
                            进程内，受 files.roots 约束
```

| | 谁执行 | 受什么约束 |
|---|---|---|
| **同步** | 技能脚本（子进程） | 沙箱：`mode` + `write_paths`（Seatbelt / Landlock 强制） |
| **读取** | 内置工具（进程内） | `files.roots`，每次调用解析符号链接后判断越界 |
| **谁能用** | Agent 定义 | `skills:` / `mcp:` 按 Agent 分配 |

## 配置

Web 控制台左侧的**「代码」**页就是这一段的界面：加目录、看每个目录下识别到哪些项目、哪些目录还不存在（同步任务没跑过），保存即热重载。服务端会拒绝把 agent 自己的配置/状态目录设为代码目录。

```yaml
# 代码目录：不配这一段，read_file / list_dir / grep_files 根本不注册
files:
  roots:
    - /data/repos

sandbox:
  mode: workspace              # 全局默认：不能出网
  backend: os
  write_paths:
    - /data/repos              # 只有同步脚本要写这里

agents:
  - name: CodeAnalysis
    description: 分析已同步的代码库，定位实现、评估改动影响
    skills: [repo-sync]        # 只有它能跑同步
  - name: OrchestrationAgent
    skills: []                 # 协调者碰不到代码技能
```

`files.roots` 里的目录会**自动同时对沙箱脚本可读**，不用在 `sandbox.read_paths` 里再写一遍——两份清单迟早会漂。

## 同步技能

`~/.jelly-agent/skills/repo-sync/SKILL.md`：

```markdown
---
name: repo-sync
description: 把配置的项目代码同步到本地供分析
enabled: true
sandbox: workspace-net
---
调用 run_script 运行 sync.sh，它会把所有项目 git pull 到最新。
```

`sandbox: workspace-net` 是**收紧**不了的地方——出网必须全局 `mode` 就允许。技能只能比全局更严，所以要么全局 `workspace-net`，要么这个技能单独走 docker 后端。

脚本 `sync.sh` 里的 git 凭据用**技能变量**注入（Web 技能页 → 该技能 → 变量），值不进对话、别的技能也拿不到。

周期任务（Web 周期任务页）选中这个技能，cron 填 `0 3 * * *`，每天凌晨同步一次。

## 工具怎么用

给模型的路径都是**相对代码目录根**的，它读回来的路径可以直接再传进去：

```
grep_files(pattern="func.*Handler", glob="*.go")   → project-a/internal/x.go:42
read_file(path="project-a/internal/x.go", offset=30, limit=60)
list_dir(path="project-a/internal")
```

内置的保护：
- `.git` / `node_modules` / `vendor` / `dist` / `target` 等目录不扫
- 二进制文件不读（首 8KB 有 NUL 就跳过）
- 单次读 400 行 / 256KB 封顶，grep 100 条匹配封顶
- 单行超过 400 字符截断（压缩过的文件一行能有一兆）

## 隔离到底有多真

**真的**：
- 路径越界在**解析完符号链接之后**判断。仓库里 checkin 一个指向 `/etc` 或指向 `~/.jelly-agent` 的软链，跟不出去——这是 `fileroots_test.go` 专门测的用例。
- 脚本的读写边界由 Seatbelt / Landlock 强制，不是靠脚本自觉。
- 技能和 MCP 按 Agent 分配，别的 Agent 拿不到代码技能。

**不是的**：
- **根目录本身选错了，越界检查救不了你**。别把 `~/.jelly-agent` 写进 `files.roots`——那里面是 API key 和会话库。
- 文件工具跑在**进程内**，不受沙箱管。约束它们的是 `files.roots`，不是 Landlock。
- 如果你改用 stdio 的 filesystem MCP：**MCP 子进程完全不走沙箱**（`internal/mcp/mcp.go` 直接 exec），隔离全靠那个 server 自己的 root 参数。

## 上下文预算

多个项目的代码远超上下文窗口，别指望「把代码喂给模型一起分析」。正确的用法是让模型**先搜后读**：`grep_files` 定位，`read_file` 只取需要的那几十行。工具的默认上限就是照这个路径设计的。

真要做全库级的结论（架构梳理、依赖全景），先用脚本跑聚合（`cloc`、依赖图、调用图），把**结果**喂给模型，而不是源码。
